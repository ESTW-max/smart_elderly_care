# 跨包开发指南

## 开发前

1. 先读任务的 PRD、设计、实现计划和目标 package 的 spec。
2. 搜索是否已有相同模型、请求封装、service 或组件；只在出现第二个真实消费者时提取共享抽象。
3. 画出本次数据流：`OpenAPI YAML → 生成的 TypeScript 类型 → uni.request → FastAPI schema/route → service → SQLAlchemy`。
4. 为每个边界写清字段、空值、校验责任、状态码和错误显示。

## 修改时

1. 一个任务形成一个可验证的垂直切片；字段或端点变更必须同时修改 FastAPI、YAML、生成类型、前端调用和测试。
2. 页面不复制接口类型，路由不承载可复用业务/数据库逻辑。
3. 平台无关代码只用 `uni.*`；平台专属能力使用条件编译并提供降级路径。
4. 不把 `.env`、密钥、证书、数据库文件或平台构建产物提交到 Git。

## 完成前

1. 运行 `pnpm run check`、`pnpm run test:api`、`pnpm run lint:api`，以及受影响的平台构建。
2. 用空数据、错误类型、边界长度、未知 ID 和网络失败检查跨层行为。
3. 本地检查失败时记录真实原因，不静默跳过。
4. 把稳定约定回写到对应 spec，不只留在聊天记录中。
